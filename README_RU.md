## 👋 Что это за репозиторий?

`v2ray-configs` собирает и упорядочивает предоставленные сообществом профили подключения, совместимые с V2Ray, и публикует файлы подписок для поддерживаемых клиентов. Цель проекта — упростить поиск конфигураций с помощью автоматических проверок и распределения результатов по полезным категориям качества.

**Ссылка подписки** — это URL, который добавляется в совместимый клиент. Клиент загружает по нему актуальный список, поэтому при обновлении списка не нужно импортировать каждый профиль по отдельности. Доступность и совместимость могут меняться, поэтому успешная проверка отражает состояние только на конкретный момент и не гарантирует бесперебойную работу, скорость, безопасность или доступность во всех регионах.

> **Используйте ответственно.** Соблюдайте действующие для вас законы и правила использования сети. Конфигурации предоставляются сообществом и могут направлять трафик через сторонних операторов. Не используйте ненадёжные профили для конфиденциальных задач. Проект не управляет всеми серверами из индекса и не одобряет их автоматически.

## 🚀 Быстрый старт

1. Установите клиент, совместимый с V2Ray, для своей платформы — например, v2rayNG, V2RayN или клиент со стандартными URL подписок.
2. Скопируйте URL подписки ниже.
3. В клиенте выберите **Добавить подписку / Импортировать из URL**, вставьте ссылку, обновите подписку и выберите профиль.

## 🧪 Как работает фильтрация

На каждом этапе набор постепенно сужается. Конкретные тесты и пороговые значения необходимо поддерживать в соответствии с автоматизацией этого репозитория.

| Этап | Название | Что происходит |
|---|---|---|
| **L0** | Приём | Сбор кандидатов, нормализация поддерживаемых URI/форматов конфигураций и удаление некорректных или дублирующихся записей. |
| **L1** | Валидация | Проверка обязательных полей, поддерживаемых протоколов, возможности разбора и базовых правил политики до добавления кандидата в рабочий индекс. |
| **L2** | Доступность | Запуск настроенных проверок соединения/работоспособности и запись результата с временной меткой. Неудачная проверка также может быть вызвана временными проблемами сети. |
| **L3** | Ранжирование и публикация | Применение правил категорий, ранжирование подходящих записей при наличии измерений и формирование файлов подписок и данных панели. |

```text
Источники сообщества → приём L0 → валидация L1 → проверки работоспособности L2 → отбор L3 → подписки
```

После неудачной проверки при следующем запуске профиль может перейти в другую категорию или исчезнуть из списка. Автоматические проверки — это индикаторы, а не полноценный аудит безопасности. Репозиторий не гарантирует шифрование сверх возможностей выбранного протокола; обозначение «безопасный» не является независимой сертификацией безопасности.

## 🏗️ Кратко об архитектуре

```text
Источники
  └─► Сборщик / нормализатор
        └─► L0–L1: удаление дубликатов, разбор, валидация
              └─► L2: плановые проверки работоспособности
                    └─► L3: классификация и ранжирование
                          ├─► top100.txt
                          ├─► subscriptions/{verified,fast,secure,all}.{txt,json,yaml}
                          ├─► index.json + health.json
                          └─► панель
```

- **Автоматизация:** запланированный workflow обновляет данные источников, выполняет настроенные проверки и публикует созданные артефакты. Историю запусков можно посмотреть в [Actions](https://github.com/YOUR_GITHUB_USERNAME/v2ray-configs/actions).
- **Единый источник истины:** `index.json` должен содержать актуальное общее количество в поле `total`; `health.json` — актуальное число работающих записей в `online` и временную метку ISO-8601 в `checked_at`.
- **Динамические badges:** расположенные выше динамические JSON badges Shields.io напрямую считывают эти поля из JSON-файлов ветки `main`. При изменении модели данных сохраняйте эту схему или обновите запросы badges. Для отображения badges общедоступные файлы должны открываться без аутентификации и содержать корректный JSON.
- **Сгенерированные результаты:** файлы подписок и данные панели должны создаваться конвейером, а не редактироваться вручную. Если фактические каталог или имена выходных файлов отличаются, скорректируйте ссылки категорий.
- **Панель:** badge ведёт на GitHub Pages по адресу `https://YOUR_GITHUB_USERNAME.github.io/v2ray-configs/`. Если проект размещён на другой платформе, замените его на URL опубликованной панели.
